# Eternal World 改造计划（基于 Source of Mana）

> 本文件记录改造范围与已核实事实。当前分支只做隔离和技术审计，不宣称尚未实现的功能已经完成。

## 项目基线

- 上游项目：Source of Mana
- 上游仓库：https://github.com/sourceofmana/sourceofmana
- 本项目：Eternal World
- 当前改造分支：`ew/mobile-first`
- 引擎：Godot 4；项目配置标注 Godot 4.7
- 目标平台：Android APK 与手机浏览器 Web（HTML5/WebAssembly）
- 代码许可：MIT；美术与设计资源按上游 LICENSE.md 的 CC BY-SA 4.0 及逐项署名清单处理。

## 已核实的现状

1. 项目 README 声明支持 Android 和 Web 客户端。
2. 当前输入服务 `sources/input/Action.gd` 已处理 `InputEventScreenTouch`、`InputEventScreenDrag`，并从 `Launcher.GUI.sticks.GetMove()` 获取虚拟摇杆向量；因此不能把“完全没有触屏输入”当作事实。下一步应在真实手机上验证摇杆布局、按钮触控区域、缩放与交互冲突。
3. `project.godot` 当前显示产品名为 Source of Mana、版本 0.0.9、Godot 特性版本 4.7。
4. `export_presets.cfg` 已包含 Android 与 Web 导出预设；是否能成功导出仍需匹配 Godot 导出模板、Android SDK/JDK 和 Web 构建环境实测。
5. 存档、掉落、交易、技能等现有系统必须先追踪客户端/服务器权威边界，不能只改客户端数值而造成多人同步或作弊问题。

## 产品目标

### P0：先让手机端可玩、可验证
- 中文化核心菜单、设置、角色状态、背包、技能、任务、NPC交互。
- 验证并优化手机虚拟摇杆、触控按钮、界面缩放和横竖屏布局。
- 提供单人/离线体验的可行性评估；若现有网络架构强依赖服务器，先明确依赖，不伪装成离线模式。
- 验证 Android 与 Web 两种导出路径。

### P1：核心 RPG 玩法
- 角色：夏叶为玩家角色；莉娅作为伙伴/NPC的实现方式先做技术验证。
- 战斗：武器攻击距离、攻击速度、命中判定、技能冷却倒计时。
- 装备：装备槽、属性修正、穿戴外观与数值一致。
- 掉落：怪物独立掉落表，铜币、材料、装备分层；精英怪有独立稀有掉落规则。
- 背包：堆叠、使用、装备、出售、丢弃，数量与交易结果一致。
- 成长：经验、等级、属性点、技能点与成长曲线可配置。

### P2：内容扩展
- 村庄地图、商店、铁匠、炼金师、任务 NPC。
- 材料配方与制作闭环。
- 森林、洞穴、地下城、精英怪与 Boss。
- 扩展怪物、武器、防具、饰品和技能池。

## 开发与验收规则

- 所有改动只提交到 `ew/mobile-first` 分支；不直接改动 `master`。
- 每个功能必须说明：涉及文件、数据流、客户端/服务器责任、测试步骤和结果。
- 不接受只有界面、没有真实状态变化的假功能。
- 手机实测前不得标记“移动端通过”；没有成功构建前不得声称 APK/Web 已可下载。
- 美术素材必须检查原始来源、授权、署名与 ShareAlike 要求；不能仅凭素材包页面标题判断全部资源许可。
- 存档改动必须验证旧存档兼容、保存、重启读取和异常恢复。

## 第一批技术任务

1. 完成输入与 UI 的移动端审计，确认虚拟摇杆、触控点击、长按、缩放和 UI 消费事件的行为。
2. 梳理玩家移动、攻击、技能、背包、装备、掉落、交易的脚本入口与网络同步边界。
3. 检查 Web/Android 导出预设及依赖，建立可重复构建说明。
4. 完成上述审计后再实施最小可运行的中文移动端测试版本。
