# 主动质量审查清单（每轮构建前必须执行）

本清单是开发门禁，不是可选的上线后检查。发现问题先记录、修复、复测，再交付给玩家。

## 本次主动审查发现（2026-11-11）

审查范围：角色创建界面、角色外观选项、登录入口、项目本地化配置。

### 已确认问题

1. **角色创建界面仍有英文可见文本。**
   - `presets/gui/Character.tscn` 中存在 `Enter Character Name`、`Attributes`、`Strength`、`Vitality`、`Agility` 等英文。
   - `sources/gui/character/Character.gd` 中错误提示仍有多处英文，例如角色名不可用、连接超时、名称长度错误等。
   - 登录脚本 `sources/gui/Login.gd` 中也存在英文错误提示。
   - 结论：此前“全中文”的范围定义和验收不合格，不能只汉化新加的物品/怪物名。

2. **性别选项必须双向可选，且默认值必须明确。**
   - `sources/gui/character/Traits.gd` 有男女切换逻辑，显示文字为“男/女”。
   - 但 `genderValue` 初始值是 0；`Character.gd` 缺失角色信息时默认使用 `ActorCommons.Gender.MALE`。必须核对 Gender 枚举数值、角色创建场景首次初始化、随机外观逻辑和提交服务器的数据，不能只看单个脚本。
   - 交付要求：创建角色时明确显示“性别：男 / 女”，两个选项均可点击；默认男性（如用户未另行指定），切换后预览模型和最终创建数据一致；删除/重新创建/随机外观均不得悄悄重置为女性或单一性别。
   - 必须分别创建男性角色和女性角色各一次，检查预览、保存、重新登录后的性别与模型。

3. **项目没有建立可验证的完整简体中文本地化门禁。**
   - 当前项目配置中未看到已配置的翻译资源入口。
   - 不能仅凭新增文档或部分界面中文宣称“全部汉化”。
   - 必须覆盖：启动/登录/账号注册/角色创建/服务器选择/主 HUD/菜单/设置/背包/物品详情/装备/技能/任务/对话/商店/交易/战斗提示/系统通知/错误弹窗/退出确认。

## 每轮发布前的主动纠察流程

### A. 静态文本扫描
- 扫描所有玩家可见的 `.tscn`、`.tres`、`.gd`、JSON、配置和数据文件。
- 检查英文 UI 文案、硬编码提示、占位符、物品/技能/怪物名、NPC 对话、错误提示。
- 内部代码标识符、资源路径、协议字段和第三方版权信息可以保留英文；玩家可见内容不可以因为“难翻译”而遗漏。
- 输出逐项清单：文件、行/节点、当前文本、建议中文、是否已修复。

### B. 角色创建专项测试
- 男/女均可选择，不得缺选项。
- 默认值符合产品要求。
- 选项切换时人物预览正确。
- 随机外观不会强制固定某一性别。
- 创建请求传递正确性别枚举。
- 存档后重进，性别与外观保持一致。
- 手机触屏可以准确点选，不依赖鼠标悬停。

### C. 全流程中文验收
按真实玩家路径逐屏检查：
启动 → 登录/本地进入 → 角色创建 → 进入村庄 → NPC 对话 → 接任务 → 战斗 → 掉落 → 背包 → 装备 → 商店 → 存档 → 重进。
任何一个可见英文按钮、标题、提示、物品说明或错误文本都登记为未通过。

### D. 手机实机验收
- Android 触控区域、文字大小、中文字体字形、横竖屏/安全区、键盘弹出遮挡。
- 男女选项和所有关键操作必须能通过触屏完成。
- 检查字体是否缺字、乱码、溢出、截断。
- 测试中断网络、背包满、余额不足、错误输入等异常分支，提示同样必须中文。

### E. 交付纪律
- 不以“代码写完”替代“构建成功”。
- 不以“静态扫描通过”替代“手机实测通过”。
- 不以“新增中文数据”替代“全流程汉化”。
- 交付报告必须区分：已修复、待修复、已构建、已实机测试、未验证。
- 用户指出问题后，先复现和定位，不让用户承担测试人员职责；开发者主动检查相邻页面和同类问题。

## 本轮立即整改范围

优先处理角色创建与入口链路：
1. 角色创建界面所有英文静态文本。
2. 登录、注册、角色创建错误提示。
3. 性别选项明确呈现男/女，默认男性，预览和保存一致。
4. 建立全项目可见文本扫描清单，再按模块推进汉化。
5. 修复后构建并提供可测试版本；未构建前不得宣称完成。
