# 汉化与角色创建质量门禁

本清单是每轮交付前的必检项。它记录真实验收要求，不代表尚未执行的测试已经通过。

## 产品启动规则

- 不显示账号注册、账号登录、密码、找回密码或服务器选择界面。
- 首次启动：直接进入角色创建。
- 已有本地存档：自动读取并进入上次游戏状态。
- 断开网络后仍可启动、创建角色、探索、战斗、保存和重新读取。
- 不允许用自动创建隐藏账号、固定密码或本机认证 RPC 冒充真正的无账号单机模式。

## 汉化范围

必须覆盖所有玩家可见内容：
- 启动、角色创建和角色外观选项。
- 主 HUD、菜单、快捷栏、状态提示。
- 角色属性、背包、装备、物品详情。
- 技能、任务日志、魔物图鉴。
- NPC 对话、商店、交易、制作。
- 战斗提示、掉落提示、升级提示。
- 设置、错误弹窗、存档提示、退出确认。

内部代码标识符、资源路径、数据库键值、网络协议字段和依法必须保留的版权信息可以使用英文；不得因此遗漏玩家可见文本。

## 字体与排版

- 检查简体中文常用字、标点和特殊符号是否有字形。
- 检查标题、按钮、物品名称、长描述的换行、截断和溢出。
- 检查字体在 Android 导出包中是否实际包含，不能依赖开发电脑恰好安装的系统字体。
- 手机端检查字号、触控区域、键盘弹出遮挡和安全区。

## 角色创建专项

- 男性、女性选项均明确显示且可触控选择。
- 性别切换后预览模型同步变化。
- 随机外观不能意外覆盖用户选择的性别。
- 创建时提交的性别与预览一致。
- 保存并重新启动后，角色性别、外观和姓名保持一致。

## 本地存档专项

- 首次启动进入创建角色。
- 创建后自动保存。
- 手动保存可用并给出中文反馈。
- 退出重启后恢复角色、背包、装备、任务、地图位置和世界状态。
- 断网状态下重复测试。
- 异常退出后检查存档完整性与恢复行为。

## 每轮检查流程

1. 扫描玩家可见的 `.tscn`、`.tres`、`.gd`、JSON、配置和数据文件。
2. 输出英文残留清单：文件、节点/行、原文、中文建议、处理状态。
3. 对照真实启动路径逐屏检查，不再把登录/注册作为目标流程。
4. 执行 Godot 解析/导入检查和自动化测试。
5. 构建 Android 包；记录构建产物和 Actions 结果。
6. 在真实 Android 设备上验证中文字体、触控、断网启动和本地存档。

## 交付状态必须分开记录

- 已修改代码
- 已提交 GitHub
- 静态检查通过
- 自动化测试通过
- Android 构建成功
- Android 实机通过
- 离线与存档测试通过

任何未实际执行的项目都标记为“未验证”，不得宣称完成。
